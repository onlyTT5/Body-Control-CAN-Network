# CAN 协议

## 1. 公共参数

- 波特率：500 kbit/s
- 标识符：11 位标准 ID
- 帧类型：数据帧
- DLC：8
- 多字节整数：小端序，低字节在前
- 未定义/保留字节：发送 `0x00`

## 2. 控制与状态报文

### `0x100` LIGHT_CONTROL（节点 A → 节点 B）

| 字节 | 定义 |
|---|---|
| B0 | bit0：目标灯光，0=关，1=开 |
| B1 | 命令序号 |
| B2–B7 | 保留 |

### `0x101` HEARTBEAT（节点 B → 节点 A）

| 字节 | 定义 |
|---|---|
| B0 | 心跳序号，循环递增 |
| B1 | bit0：`needs_sync`，1=请求节点 A 重新同步灯光状态 |
| B2–B7 | 保留 |

### `0x102` LIGHT_STATUS（节点 B → 节点 A）

| 字节 | 定义 |
|---|---|
| B0 | bit0：实际灯光状态 |
| B1 | 已处理的命令序号 |
| B2–B7 | 保留 |

### `0x111` PARK_DISTANCE（节点 B → 节点 A）

| 字节 | 定义 |
|---|---|
| B0 | bit0：距离有效 |
| B1–B2 | 距离，单位 mm，`uint16` 小端 |
| B3 | 测量序号 |
| B4–B7 | 保留 |

### `0x114` HEALTH_STATUS（节点 B → 节点 A）

| 字节 | 定义 |
|---|---|
| B0 | 健康标志位 |
| B1 | 最近一次复位原因 |
| B2 | CAN Last Error Code（LEC） |
| B3 | 诊断序号 |
| B4–B7 | 节点 B 运行时间，ms，`uint32` 小端 |

B0 健康标志：

| 位 | 掩码 | 含义 |
|---|---|---|
| bit0 | `0x01` | 超声波数据无效 |
| bit1 | `0x02` | CAN error warning |
| bit2 | `0x04` | CAN error passive |
| bit3 | `0x08` | CAN bus-off |
| bit4 | `0x10` | 本次启动检测到 IWDG 复位 |

## 3. 事件日志协议

### 查询请求 `0x103`（测试端 → 节点 A）

普通查询：B0 为倒序偏移，`0x00` 表示最新一条，`0x01` 表示倒数第二条，其余字节为 0。

```text
查询最新：00 00 00 00 00 00 00 00
查询上一条：01 00 00 00 00 00 00 00
```

受保护清除命令：

```text
FF 43 4C 52 A5 5A 00 00
```

### 摘要响应 `0x104`（节点 A → 测试端）

| 字节 | 定义 |
|---|---|
| B0 | 状态：0=成功，1=不存在，2=Flash 读取错误 |
| B1 | 请求的倒序偏移 |
| B2 | 事件类型 |
| B3 | 事件数据 0 |
| B4 | 事件数据 1 |
| B5–B6 | 当前存储条数，`uint16` 小端 |
| B7 | 保留 |

### 明细响应 `0x105`（节点 A → 测试端）

| 字节 | 定义 |
|---|---|
| B0–B3 | 日志序号，`uint32` 小端 |
| B4–B7 | 记录时间戳，ms，`uint32` 小端 |

事件类型：

| 值 | 含义 |
|---:|---|
| `01` | 启动 |
| `02` | CAN 上线 |
| `03` | CAN 离线 |
| `04` | 灯光命令 |
| `05` | 灯光应答 |
| `06` | 灯光应答超时 |
| `07` | 诊断故障确认 |
| `08` | 诊断故障恢复 |
| `09` | 远端节点复位 |
| `0A` | 健康报文诊断序号跳变 |

## 4. DTC 协议

### 请求 `0x115`（测试端 → 节点 A）

| B0 | 操作 |
|---|---|
| `00` | 查询摘要 |
| `01`–`06` | 查询指定 DTC 明细 |
| `FF` | 清除命令；必须同时带完整保护字节 |

示例：

```text
摘要查询：00 00 00 00 00 00 00 00
DTC 01：  01 00 00 00 00 00 00 00
DTC 06：  06 00 00 00 00 00 00 00
清除：    FF 43 4C 52 A5 5A 00 00
```

### 摘要响应 `0x116`

| 字节 | 定义 |
|---|---|
| B0 | 状态，成功为 0 |
| B1 | `00`，表示摘要 |
| B2–B3 | 当前激活掩码，`uint16` 小端 |
| B4–B5 | 历史/已存储掩码，`uint16` 小端 |
| B6 | 当前激活数量 |
| B7 | 历史/已存储数量 |

例如 `00 00 00 00 03 00 00 02` 表示当前无激活故障，历史掩码为 `0x0003`，共 2 个历史 DTC。

### 明细响应 `0x116`

| 字节 | 定义 |
|---|---|
| B0 | 状态 |
| B1 | DTC 编号 |
| B2 | 当前激活：0/1 |
| B3 | 历史已存储：0/1 |
| B4 | 连续失败计数 |
| B5 | 连续通过计数 |
| B6–B7 | 累计确认次数，`uint16` 小端 |

若该 DTC 有有效冻结帧，明细响应后还会发送 `0x117` 与 `0x118`。如果当前无冻结帧，只返回 `0x116`，且 B0 为 `0x02`。

### 冻结帧数据 `0x117`

| 字节 | 定义 |
|---|---|
| B0 | 状态 |
| B1 | DTC 编号 |
| B2 | 故障确认时的健康标志 |
| B3 | 故障确认时的 CAN LEC |
| B4 | 故障确认时的远端复位原因 |
| B5 | 距离有效：0/1 |
| B6–B7 | 故障确认时的距离 mm，小端 |

### 冻结帧时间 `0x118`

| 字节 | 定义 |
|---|---|
| B0 | 状态，成功为 0 |
| B1 | DTC 编号 |
| B2–B3 | 节点 A 本地时间，秒，`uint16` 小端 |
| B4–B5 | 节点 B 运行时间，秒，`uint16` 小端 |
| B6–B7 | 保留 |

### 清除响应 `0x116`

格式与摘要响应相同，但 B1 为 `FF`。状态码：

| 状态 | 含义 |
|---:|---|
| `00` | 成功 |
| `01` | DTC 编号无效 |
| `02` | 无冻结帧 |
| `03` | 存在当前激活故障，拒绝清除 |
| `04` | Flash 存储操作失败 |

## 5. DTC 编号

| 编号 | 含义 |
|---:|---|
| `01` | 超声波数据持续无效 |
| `02` | 节点 B 通信离线 |
| `03` | CAN error warning |
| `04` | CAN error passive |
| `05` | CAN bus-off |
| `06` | 节点 B 看门狗复位历史 |

## 6. 解析注意事项

- `active=0`、`stored=1` 是“故障已恢复但历史仍存在”，属于正常状态。
- 明细中的累计次数不是 DTC 编号；例如 `C:00002` 表示该故障累计确认两次。
- 冻结帧保存的是故障首次确认时的快照，不会跟随当前实时数据变化。
- 查询请求不要设置为高频周期发送；手动查询或使用较长周期，避免诊断响应淹没正常周期报文。
