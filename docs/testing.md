## 6. 事件日志

使用标准帧、DLC 8 发送：

```text
ID 0x103  00 00 00 00 00 00 00 00
```

应收到 `0x104` 和 `0x105`。把 B0 改为 `01`、`02`，确认可倒序读取旧记录。复位后再次查询，确认日志仍存在。

清除测试：

```text
ID 0x103  FF 43 4C 52 A5 5A 00 00
```

清除后查询最新记录，状态应显示不存在或只包含清除后新产生的事件。

## 7. DTC 与冻结帧

### 摘要

```text
ID 0x115  00 00 00 00 00 00 00 00
```

检查 `0x116` 的激活掩码、历史掩码和数量相互一致。

### 明细

```text
ID 0x115  01 00 00 00 00 00 00 00
```

应收到 `0x116`；有冻结帧时继续收到 `0x117`、`0x118`。对 DTC 01–06 逐项查询，确认编号、激活、历史、计数和冻结帧能正确解释。

### 清除

```text
ID 0x115  FF 43 4C 52 A5 5A 00 00
```

- 当前故障已恢复：返回状态 0，历史掩码清零。
- 当前故障仍激活：返回状态 3，记录保持不变。
- 复位后再次查询，确认清除结果已持久化。

## 8. 通信故障恢复

1. 正常运行时断开节点 B 的 CAN 连接或电源。
2. 节点 A 超时后显示 `CAN OFFLINE`，DTC 02 最终进入 active/stored。
3. 恢复连接或电源。
4. 检查 `0x101`、`0x111`、`0x114` 恢复，节点 A 重新同步灯光目标。
5. 连续收到恢复条件后，DTC 02 的 active 清零、history 保留。
6. 整个过程中 OLED、按键和本地任务不应停止响应。

## 9. CAN 错误与 bus-off

在安全的台架环境中制造通信中断或使用测试工具注入错误，检查 warning、passive、bus-off 标志与 DTC 03–05。恢复物理总线后，周期报文应自动恢复，历史故障应保留。

不要在真实车辆网络上进行错误注入或短接测试。
